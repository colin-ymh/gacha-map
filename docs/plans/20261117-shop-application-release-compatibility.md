# 사업자등록 동시 출시 호환성

## Request

둘러보기와 사업자등록 변경을 함께 출시한다. 이미 배포된 앱의 샵 신청 경로도 계속 동작해야 한다.

## Scope

- 앱 2.1.0이 사용하는 기존 JSON 제출과 새 웹·앱 제출을 같은 API에서 병행한다.
- 새 요청은 API 버전 2로 표시한다. 개인정보 동의와 신규 샵 증빙을 서버에서 계속 검증한다.
- 구버전 요청은 이미 운영 중인 신청 항목을 받는다. 서버가 확인한 동의와 제출 서류가 없으면 해당 값을 `null`로 남긴다. 사업자등록번호·중복·소유권과 좌표 검증은 두 버전에 공통 적용한다.

## Out of Scope

화면 배치, 신청 항목, 저장소 접근 정책 및 DB 스키마 변경. 구버전 경로 종료는 스토어 공개 후 기존 앱 지원 기간과 사용률을 확인해 결정한다.

## Relevant Files

- `apps/web/src/app/api/shop-applications/route.ts` 및 관련 회귀 테스트
- `apps/mobile/app/shop-application.tsx` 및 웹 사업자 신청 폼의 요청 경로
- `docs/api-contracts.md`, `docs/pending-prod.md`
- [Notion 사업자 샵 등록 기획](https://app.notion.com/p/36c203d520db8164945eeb078feb1382)

## Plan

1. 기존 JSON 요청에만 이전 계약을 적용한다. 새 웹·앱은 POST 쿼리의 `version=2`로 엄격한 계약을 항상 사용한다.
2. 구버전 신규 신청 주소는 공통 지오코딩 경로에서 좌표를 보완한다. 좌표를 확인할 수 없으면 DB에 등록하지 않는다.
3. 두 계약을 테스트한 뒤 스테이징에서 스토어용 구버전 요청과 신규 앱·관리자 흐름을 검증한다. 운영 적용은 기존 배포 절차를 따른다.

## Verification

- 2.1.0 형식의 신규 등록 및 소유권 신청 성공, 동의·증빙 미기록, 주소로 좌표 보완.
- v2의 동의 누락·철회, 신규 등록 증빙 누락, 잘못된 버전 거절. 기존 프리뷰의 동의 포함 JSON과 multipart 요청에는 v2 검증 적용.
- 두 버전의 중복, 소유자가 있는 샵, 지오코딩 실패 및 관리자 승인. 웹 테스트·타입 검사와 모바일 타입 검사 및 iPhone 프리뷰.

## Risks / Questions

- 구버전 JSON은 명시적 동의와 파일 첨부를 제공할 수 없다. 호환 경로는 배포 앱과 같은 신청 데이터만 받으며, 새 앱이나 웹에서 보내는 v2 요청에는 적용하지 않는다.
- 구버전에서 직접 입력한 주소를 지오코딩할 수 없는 경우 신규 등록은 오류를 반환한다. 매장 좌표를 임의로 저장하는 대신 해당 주소를 확인해야 한다.

## Adversarial Review

- 버전 생략만으로 동의 검증을 건너뛰면 이전 프리뷰나 첨부가 있는 신규 요청도 완화될 수 있다. 별도 버전, JSON 미디어 타입, 동의 필드 부재를 함께 확인한다.
- 명시적으로 동의를 거절한 요청에는 호환 경로를 적용하지 않는다.
- 구버전 신청도 관리자 승인 및 DB 보호 조건을 거친다. `null`은 동의·증빙 확인 전 상태를 정확히 보존한다.

## Final Plan

POST 경로에서 계약을 선택하고 공통 검증·저장·승인 경로를 재사용한다. 신·구 앱 요청 형식, 서류 보안, 지오코딩 실패를 테스트하고 운영 체크리스트에 단계별 결과를 기록한다.
