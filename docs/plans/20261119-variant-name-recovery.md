# 구성품 이름 표시와 Collector 이름 품질 자동 점검

## Request
공식 이름 없는 구성품은 번호로 정상 표시한다. 이미지로 새 이름을 만들지 않는다. Collector가 실제 번역 누락을 감지·재처리하고 다음부터 수동 점검에 의존하지 않도록 보완한다.

## Scope
- 상품 대표명과 구성품 이름의 상태를 구분한다.
- 이름 있는 구성품은 한국어명, 이름 없는 구성품은 기존 sort_order 기반 구성품 N을 표시한다.
- 운영 앱의 기존 표시 코드를 지원하도록 소비자 API 응답에 표시용 한국어 fallback을 제공하고 원래 이름 상태를 함께 반환한다. DB의 name_ko에는 번호를 번역으로 저장하지 않는다.
- Collector의 이름 품질 보고와 정기 workflow에 자동 검사 및 실패 신호를 연결한다.
- 원문 이름이 있는 번역 누락만 기존 텍스트 번역 경로에서 재처리한다.

## Out of Scope
유료 이미지 판독/OCR 복구, 임의 공식 이름 생성, DB 이름 일괄 번호 채우기, 스키마/환경값 변경, UI 레이아웃 변경, 모바일 스토어 배포.

## Relevant Files
- apps/web/src/lib/gacha/variantNames.ts, rollStats.ts
- 가챠 구성품/뽑기/기록/컬렉션 API와 공유 화면의 이름 표시
- Collector scripts/generate-gacha-variant-ko-names.ts
- Collector 신규 이름 품질 검사기 및 biweekly-collector.yml, 일일 읽기 전용 검사 workflow
- docs/api-contracts.md의 해당 API 설명

## Spec
[Notion 가챠 돌려보기 기획](https://app.notion.com/p/38c203d520db81b8959ffb27760bfffa)을 확인했다. 기존 문서는 한국어명→일본어 원문 fallback을 기술한다. 2026-11-19 사용자는 한국어명 우선, 이름 없는 구성품은 이미지+구성품 번호로 표시하는 정책을 승인했다. 이 최신 요청을 적용한다. 레이아웃/컴포넌트 배치는 바꾸지 않는 문구·응답 표시 수정이므로 Penpot 동기화 대상이 없다.

## Plan
1. 공식 원문 유무와 한국어명 유효성, 기존 표시 경로를 확인한다.
2. API의 이름 표시를 공통 함수로 처리한다. 이름 상태 translated/translation_pending/unnamed와 표시명을 반환하고 기존 클라이언트 name_ko에는 번호 fallback을 전달한다.
3. 목록·뽑기·최근 기록·통계·컬렉션·공유에서 같은 구성품 번호를 사용한다. sort_order가 없으면 임의 목록 index를 재번호로 만들지 않는다.
4. Collector의 기존 번역기는 원문 이름 없는 행을 번역 대상에서 제외하고 실제 실패 시 실패 코드를 반환한다. 실제 번역 누락은 기존 재처리 흐름에 남긴다.
5. 읽기 전용 이름 품질 검사를 추가한다. 이름 없는 구성품은 정상으로 집계하고, 활성 상품명 누락과 원문 있는 구성품의 번역 누락은 실패 처리한다. 전체 수와 제조사별 분포를 보고한다.
6. 수집 성공/실패와 무관하게 실행 후 품질 검사를 수행하고, 일일 읽기 전용 점검도 실행한다. 추가 이미지 AI 호출은 없다.
7. 단위·API·전체 web 검사와 Collector 테스트, 운영 읽기 전용 품질 검사 및 공개 API 표본으로 검증한다.

## Verification
- null/공백/일본어 잔존 한국어명과 원문 유무를 구분한다.
- 실제 이름이 있으면 유지하고, 번호는 원래 sort_order를 사용한다. DB는 읽기만 수행한다.
- 뽑기 선택·저장 ID·쿼터·사용자 이력에는 영향이 없다.
- 이름 없는 구성품 수가 5,901개여도 정상 판정하며 실제 번역 누락 1개는 검사 실패가 된다.
- Collector의 오류가 정상 종료로 숨겨지지 않고 자동 검사 아티팩트와 작업 요약에 남는다.
- 관련 consumer API, 공유 표시 및 전체 타입/린트/테스트를 검증한다.

## Risks / Questions
- 기존 name_ko 응답은 표시 호환을 위해 번호를 포함할 수 있다. name_status로 실제 번역 여부를 구분하며 DB 원본/관리자 API는 그대로 유지한다. 계약에 명시한다.
- 공식 원문을 수집하지 못한 경우와 공식 이름이 없는 경우를 DB null만으로 단정하지 않는다. unnamed는 현재 표시 가능한 원문이 없다는 뜻이다.
- 로컬 신고/운영 자동화 관련 사용자 변경은 보존하고 커밋에 포함하지 않는다.

## Adversarial Review
- 번호를 DB에 넣으면 번역 품질 집계가 거짓 정상으로 바뀐다. API 표시에서만 번호를 만들고 검사기는 DB 원본을 본다.
- 클라이언트 수정만 하면 현재 운영 앱에는 표시 문제가 남는다. 기존 API 필드의 표시 호환을 제공한다.
- 원문 없는 항목을 계속 번역하면 비용과 실패만 쌓인다. 정상 unnamed와 실제 translation_pending을 구분한다.
- 수집 shell이 실패하면 그 뒤 검사를 건너뛸 수 있다. 품질 검사는 if: always()로 분리한다.
- 정기 검사는 실제 이름 누락만 실패시키고 정상 번호 표시 항목을 장애로 보고하지 않는다.

## Final Plan
소비자 API의 표시용 번호와 실제 DB 번역을 분리하고, 기존 Collector 재처리 + 수집 후/일일 품질 검사로 운영한다. 유료 이미지 해석과 새 스키마는 도입하지 않는다.
