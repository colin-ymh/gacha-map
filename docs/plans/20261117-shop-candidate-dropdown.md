# 사업자 등록 샵 추천 드롭다운

## Request
샵 추천을 질문 형태로 표시하고 후보는 두 곳 정도로 줄인다. 선택을 건너뛰면 직접 입력으로 진행하고, 선택 결과는 이름 필드에 남긴다.

## Scope
웹과 모바일의 후보 표시, 포커스·스크롤 동작, 이름 필드의 선택 상태와 번역.

## Out of Scope
후보 API 랭킹·상한, 신규 등록 및 소유권 신청 계약, 샵 상세에서 직접 진입하는 소유권 신청.

## Relevant Files
- 웹 사업자 등록 폼과 뷰, 모바일 `app/shop-application.tsx`, 공용 후보 훅.
- 웹·모바일 번역, Notion 사업자 샵 등록 기획 및 Penpot 후보·선택 보드.

## Plan
기존 정렬의 상위 두 곳을 샵 이름 필드에 연결된 플로팅 드롭다운으로 표시한다. 웹은 필드 기준으로 배치하고, 모바일은 폼 스크롤과 키보드에 맞춰 화면 안의 여유 있는 방향에 표시한다. 입력 필드를 벗어나면 닫는다. 기존 샵을 선택하면 같은 자리의 이름 필드에 샵명·주소·변경 액션을 표시한다.

## Verification
최대 두 곳, 정상 입력 유지, 질문 문구, 선택·취소, 등록된 사업자 안내, 폼 첨부 보존, 웹 키보드 포커스와 모바일 오버레이 배치를 검토한다. 웹 회귀 테스트와 각 워크스페이스 검사를 실행한다.

## Risks / Questions
네이티브 스크롤 자식 바깥에 놓인 요소는 터치가 잘릴 수 있다. 폼 전체 오버레이의 입력 범위 안에서 드롭다운을 배치한다.

## Adversarial Review
모바일 키보드가 키워드 입력란 아래 공간을 줄이면 드롭다운은 위쪽으로 배치한다. 직접 입력 또는 후보 선택 여부는 신청 대상 ID로 구분하고 기존 첨부와 주소 상태는 유지한다.

## Final Plan
Notion과 Penpot을 먼저 갱신하고 웹·모바일 플로팅 추천과 선택 상태를 구현한다. 후보 표시만 두 개로 제한해 기존 API 사용처를 유지한다.

## Implementation and verification
- 추천 목록의 질문 문구와 이름 필드 선택 상태를 Notion과 Penpot에 반영했다. 웹은 필드 기준 절대 배치, 모바일은 스크롤 영역 밖에서 입력 위치와 키보드 여유 공간 기준으로 배치한다.
- 웹 회귀 테스트에서 상위 두 개 노출, Escape 닫기, 이름 필드 선택 표시, 변경 및 첨부 유지, 기존 소유권 신청 제출을 확인했다. 전체 웹 테스트 402건, 공유·웹·모바일 타입 검사, iOS 개발 번들 생성을 확인했다.
- 아이폰의 키보드 및 스크롤과 후보 탭 상호작용 검증은 남아 있다.

## Follow-up
- 팝업 제목을 “혹시 이 샵의 사장님이신가요?”로 바꾸고 질문 및 후보 행의 구분선을 추가했다.
- 서버 조회는 소유자가 없는 활성 샵만 포함한다. 클라이언트는 이전 응답의 신청 불가 항목을 제외한 뒤 상위 두 곳을 표시한다.
