## 문제 1 — `line`에 브랜드가 섞여 있다

### 판정 기준 — 상품명에 외부 IP가 붙는가

제품 라인(형태)은 **IP 위에 씌우는 형식**이라 상품명이 `형태 + 외부 IP`가 된다.
브랜드는 자체 캐릭터·테마로 자기 완결하므로 외부 IP가 붙지 않는다.

각 상품명(`name_ja`)에 **활성 IP 시리즈명(4자 이상, anime/manga/game/franchise/character_brand)이
문자열로 포함되는지** 세었다 (dev, 2026-09-06).

| 카테고리          | 상품 | IP 포함 | 비율 | 판정            |
| ----------------- | ---: | ------: | ---: | --------------- |
| 카타즌            |   93 |      93 | 100% | 형태 — 유지     |
| **캡슐 플라레일** |  107 |     107 | 100% | **형태 — 유지** |
| 오네무탄          |   90 |      72 |  80% | 형태 — 유지     |
| **컵의 후치코**   |   58 |       2 | 3.4% | 브랜드 — 이관   |
| **판다의 구멍**   |   78 |       1 | 1.3% | 브랜드 — 이관   |
| **포켓토미카**    |   21 |       0 |   0% | 브랜드 — 이관   |
| **닛코리노**      |  212 |       0 |   0% | 브랜드 — 이관   |

**80%와 3.4% 사이가 비어 있다.** 경계가 데이터에서 저절로 갈린다.

### 왜 지표를 바꿨나 — 초안의 지표는 틀렸다

초안은 "연결된 **서로 다른 활성 IP 시리즈 수**"를 썼고 경계를 9와 8 사이에 그었다.
codex 적대적 검토 #7이 "표본 부족과 자기완결성을 구분하지 못한다"고 지적했고,
**교차 검증 결과 그 지적이 맞았다.**

`캡슐 플라레일`은 서로 다른 IP가 8개뿐이라 초안에서 브랜드로 분류됐다. 그러나
상품명을 보면 **107개 전부에 외부 IP가 붙어 있다.**

```
カプセルプラレール きかんしゃトーマス カーリーとサンディー編
カプセルプラレール きかんしゃトーマス あつまれ! 特殊車両編
```

IP 종류가 적었을 뿐(토마스에 집중) 자기완결적이지 않았다. 기차 완구 프랜차이즈에
토마스를 라이선스해 얹는 구조로, 오네무탄이 IP에 포즈를 씌우는 것과 형식이 같다.

→ **캡슐 플라레일을 환원 대상에서 제외한다. 대상은 5건이 아니라 4건이다.**
→ 초안의 Q1(`캡슐 플라레일` ↔ 기존 `플라레일` 이중화)도 **함께 소멸한다.**

새 지표는 링크 수가 아니라 **상품명 자체**를 보므로 수집량·파싱 품질에 덜 흔들린다.
다만 IP 시리즈명이 DB에 등재되어 있어야 잡히므로 **완벽하지는 않다** — 미등재 IP를 쓰는
형태 라인은 여전히 낮게 나올 수 있다. 아래 육안 확인을 병행한 이유다.

### 상품명 육안 확인

**형태 (브랜드 + 외부 IP)**

```
おねむたん ハイキュー!! / 呪術廻戦 / 鬼滅の刃
肩ズンFig. ハリー・ポッター2 / ディズニーキャラクター
カプセルプラレール きかんしゃトーマス ...
```

**브랜드 (자체 변형)**

```
コップのフチ子 LOVE / ピーチ / パステル / ネイビー     ← 색상·버전
パンダの穴 ミニチュアスナイパー / もちばけ            ← 자체 시리즈물
ポケットトミカ エアポート編 / 自然ツアー編            ← 자체 테마
```

### 상품명 근거 (닛코리노)

```
にっこりーノ お弁当のもこもこポーチ      닛코리노 도시락 모코모코 파우치
にっこりーノ 海鮮のぬいぐるみ3           닛코리노 해산물 봉제인형 3
にっこりーノ 学校のぬいぐるみ            닛코리노 학교 봉제인형
にっこりーノ 韓国のぬいぐるみ            닛코리노 한국 봉제인형
にっこりーノ トランプのぬいぐるみ        닛코리노 트럼프 인형
```

IP가 없다. `닛코리노`라는 자체 캐릭터에 **소재만 바꿔 다는 브랜드**다.
`오네무탄 × 주술회전`처럼 IP 위에 형태를 씌우는 구조와 다르다.

### 왜 지금 line에 있나

`20260904-toy-line-series-to-category.md`가 이들을 "오네무탄·메지루시와 같은 부류의 진짜
가챠 종류"로 판정하고 `line_patterns` 사전에 넣었다. **그 판정을 뒤집는 작업이다.**
당시 근거는 "상품 링크 88%가 line 카테고리로 커버되지 않는다"였는데, 이는 사전 미등재
문제였을 뿐 **형태냐 브랜드냐를 가리는 근거는 아니었다.**

### 대상 5건의 현재 상태

| 이름          | line 카테고리 | 원본 시리즈                 |
| ------------- | ------------: | --------------------------- |
| 닛코리노      |           212 | `toy_line` / archived (180) |
| 캡슐 플라레일 |           107 | `toy_line` / archived (70)  |
| 판다의 구멍   |            78 | `toy_line` / archived (60)  |
| 컵의 후치코   |            58 | `toy_line` / archived (51)  |
| 포켓토미카    |            21 | `toy_line` / archived (18)  |

시리즈 행이 archived 상태로 **그대로 남아 있다.** 새로 만들 필요 없이 되살리면 된다.

## 문제 2 — 대표 이미지가 축을 가로질러 충돌한다

### 증상

바로가기 쿼터를 `시리즈 2 + 라인 3`으로 바꿔도 **메지루시가 안 나온다.**

```
산리오 캐릭터즈 : tokyo-yumeya.co.jp/.../64966d32235486c18dc500d66a48e8f6-400x466.webp
메지루시        : tokyo-yumeya.co.jp/.../64966d32235486c18dc500d66a48e8f6-400x466.webp
```

URL이 완전히 같다.

### 원인

`gacha_category_browse` / `gacha_series_browse` 두 머티리얼라이즈드 뷰가 **동일한 규칙**으로
대표 이미지를 고른다 (`supabase/migrations/20260823_gacha_browse_views.sql`).

```sql
order by gp2.release_start_date desc nulls last, gp2.id
limit 1
```

클라이언트의 `usedImages` dedup이 산리오를 먼저 잡고 메지루시를 **탈락시킨다.**
썸네일 3장이 같아지는 걸 막으려는 dedup 자체는 옳다 — 문제는 **대안이 없어 항목째 버린다**는 점이다.

### 진짜 원인 — 한 이미지가 상품 50개에 붙어 있다

우연한 충돌이 아니었다. 문제의 URL을 쓰는 상품 수를 셌다.

```
tokyo-yumeya.co.jp/.../64966d32235486c18dc500d66a48e8f6-400x466.webp  →  상품 50개
```

이미지 공유 분포 (dev, active 10,100건):

| 공유 상품 수  |     이미지 개수 |
| ------------- | --------------: |
| 1개 (고유)    |           9,548 |
| 2\~4개        |             192 |
| 5\~9개        |              14 |
| **10개 이상** | **1** (최대 50) |

즉 **딱 하나의 범용 이미지가 50개 상품에 붙어 있고**, 그게 산리오와 메지루시 양쪽의
최신 상품에 걸렸다. 이 이미지를 최신 상품이 물고 있는 축은 전부 같은 썸네일을 갖게 된다.

→ 후보 복수화만으로는 부족하다. **공유도가 높은 이미지를 대표에서 밀어내야 한다.**

### 쓰레기 이미지도 섞여 있다

placeholder·UI 에셋이 상품 이미지로 수집돼 있다.

| 상품                      | URL                                                          | 정체                        |
| ------------------------- | ------------------------------------------------------------ | --------------------------- |
| 판다의 구멍 자유로운 여신 | `takaratomy-arts.co.jp/common/images/noimage_main.png`       | 이미지 없음 플레이스홀더    |
| 미마모리 필터             | `takaratomy-arts.co.jp/common/2020/images/btn_search_sp.svg` | **사이트 검색 버튼 아이콘** |

현재 `coming soon` 계열과 `official_image_url is null`은 0건이지만, 수집원이 바뀌면
언제든 들어올 수 있으므로 규칙으로 막는다.

### 문제 1을 고쳐도 해결되지 않는다

5건을 이관하면 라인 상위가 `메지루시(180) → 카타즌(93) → 오네무탄(90)`이 되지만,
메지루시는 여전히 이미지 충돌로 탈락하고 `카타즌·오네무탄·푸티또`가 뽑힌다.
**두 문제를 모두 고쳐야 요청한 5개가 나온다.**

### 해법 — 후보를 복수로 준다

메지루시는 2위 이미지부터 산리오와 겹치지 않는다.

| 순위 | 이미지                   | 상품                                 |
| ---: | ------------------------ | ------------------------------------ |
|    1 | tokyo-yumeya `64966d32…` | 거짓말 탐정 토만트 … (산리오와 충돌) |
|    2 | bandai `1000255293_1`    | MONYO FRIENDS 메지루시 액세서리      |
|    3 | bandai `1000255262_1`    | 팩맨 메지루시 액세서리 계속          |

뷰가 이미지를 **1장이 아니라 상위 N장(3장)** 돌려주고, 클라이언트가 충돌 시 다음 후보를
쓰면 항목을 잃지 않는다. 특정 이름을 하드코딩하지 않으므로 이 문제 전반에 적용된다.

### 해법 — 후보 선정 규칙 (배제 + 정렬)

**배제** — 아래는 후보에서 아예 뺀다.

| 조건                                                      | 이유                               |
| --------------------------------------------------------- | ---------------------------------- |
| `official_image_url is null` 또는 공백                    | 표시 불가                          |
| `~* 'noimage\|no[-_]image\|nowprinting\|now[-_]printing'` | 이미지 없음 플레이스홀더           |
| `~* 'coming[-_ ]?soon\|placeholder\|dummy\|準備中'`       | 준비중 플레이스홀더                |
| `~* '\.svg$'`                                             | 상품 사진이 아닌 벡터 UI 에셋      |
| `~* '/common/.*(btn\|icon\|logo)_'`                       | 사이트 공통 UI 에셋 (검색 버튼 등) |

**정렬** — 남은 후보를 아래 순으로 고른다.

```sql
order by
  share_count asc,                      -- ① 적게 공유된 이미지 우선 (범용 이미지 배제)
  gp.release_start_date desc nulls last, -- ② 그다음 최신
  gp.id                                  -- ③ 결정적 tie-break
```

`share_count`는 그 이미지를 쓰는 active 상품 수다. 분포상 99.4%가 고유(1)라
①은 평소 아무 영향이 없고, 50개짜리 범용 이미지 같은 경우에만 작동한다.

이 규칙 하나로 메지루시 문제가 풀린다 — 50개 공유 이미지가 후순위로 밀려
`MONYO FRIENDS`(고유 이미지)가 1순위가 되고, 산리오와 충돌하지 않는다.
**후보 복수화는 그래도 남는 충돌에 대한 2차 방어선이다.**

> ⚠️ 배제 규칙은 **대표 이미지 선정에만** 적용한다. 상품 상세 화면에서까지 이미지를
> 숨기면 "이미지 없음"이 아니라 "상품이 깨진 것"처럼 보인다. 상세는 현행 유지.

## Scope

1. `line` 카테고리 5건을 브랜드 시리즈로 환원 (닛코리노·캡슐 플라레일·판다의 구멍·컵의 후치코·포켓토미카)
2. collector 사전에서 해당 5건 제거 (재생성 차단)
3. 대표 이미지 선정 규칙 개선
   - 플레이스홀더·UI 에셋 배제
   - 공유도 낮은 이미지 우선 정렬
   - 후보를 상위 3장으로 확장하고 클라이언트 폴백 적용
4. dev 적용 → 확인 → prod 적용

## Out of Scope

- 나머지 `line` 카테고리 재검토 (IP 9개 이상은 형태로 판정, 유지)
- 롱테일 `toy_line` 시리즈 185건 처리 — `20260904` 문서 소관
- `other` 2,356건 재분류
- 시리즈 계층(`parent_id`) 정비
- **잘못 수집된 이미지 자체를 고치는 것.** `btn_search_sp.svg`가 상품 이미지로 들어온 건
  collector 스크래핑 버그지만, 이 문서는 "대표로 뽑지 않는다"까지만 한다.
  수집 단계 수정은 collector 리포 별건.
- 상품 상세 화면의 이미지 표시 규칙

## 반드시 지켜야 할 함정 (실측 확인)

1. **`refresh_gacha_product_categories()`가 매번 링크를 지우고 재생성한다.**

   ```sql
   delete from public.gacha_product_categories pc
   where pc.source in ('name_parts', 'known_product_line_term')
   ```

   → 사전에서 빼지 않고 DB만 정리하면 다음 배치에서 되살아난다. **collector 수정이 선행**이다.

2. **시리즈 archive는 durable하지만 링크는 아니다.**
   `refresh_gacha_product_series()`의 `on conflict do update`가 `status`를 건드리지 않는다.
   `gacha_product_series` 링크는 매 refresh마다 재생성된다.

3. **`kind` CHECK 제약**: `anime|manga|game|character_brand|toy_line|franchise|other|unknown`.

맞다. 다만 이 문서의 목표는 "깨진 이미지 0"이 아니라 "명백한 쓰레기를 대표로 뽑지 않기"다.
HTTP 검증은 배치 작업이 필요해 범위를 넘는다. `.svg?v=1` 같은 쿼리스트링 케이스만 정규식을
보강한다.

### #7 — 지적이 맞았다. 지표를 교체했고 결론이 하나 바뀌었다

**#7 (분류 지표가 분류하려는 속성을 측정하지 않는다)** — 가장 무거운 지적이었고 반박하지 못했다.

"연결된 활성 IP 수"는 수집량·파싱 품질·archive 상태·콜라보 빈도에 좌우된다.
`1/64PLUS=9`와 `캡슐 플라레일=8` 사이 경계는 **링크 하나로 뒤집힌다.**

**교차 검증 결과 이 지적이 실제 오분류를 하나 잡아냈다.**

나머지 4건을 상품명 패턴으로 다시 검증했더니(`상품명에 외부 IP 시리즈명이 포함되는 비율`),
`캡슐 플라레일`은 **107개 전부(100%)에 외부 IP가 붙어 있었다.** IP 종류가 8개로 적었던 건
자기완결적이어서가 아니라 **토마스라는 소수 IP에 집중돼서**였다. 초안 지표는 이 둘을
구분하지 못했다 — codex가 지적한 바로 그 실패 모드다.

새 지표에서는 **80%(오네무탄)와 3.4%(컵의 후치코) 사이가 비어 있어** 경계가 자의적이지 않다.
자세한 표는 위 「판정 기준」 절 참조.

→ **Q6 해소. 대상은 5건에서 4건으로 축소.**
→ Q1(플라레일 이중화)도 캡슐 플라레일이 빠지면서 **소멸.**

남은 한계: 새 지표도 **IP 시리즈명이 DB에 등재되어 있어야** 잡힌다. 미등재 IP를 쓰는
형태 라인은 여전히 낮게 나올 수 있어, 육안 확인을 병행했다.

### 설계 변경 — "시리즈 되살리기"에서 "사전의 대상 축 교체"로

초안은 archived 시리즈를 `active`로 되살리고 링크는 refresh가 재생성하길 기대했다.
**#2로 그 전제가 깨졌다** — refresh는 `name_parts.series`만 보므로 97건을 못 만든다.

바꾼다. 링크를 만드는 주체는 **사전 정규식**이므로, 사전이 꽂는 **대상 테이블만 바꾼다.**

```
현재: name_ja ~ 'にっこりーノ'  →  gacha_product_categories (relation_type='line')
변경: name_ja ~ 'にっこりーノ'  →  gacha_product_series     (relation_type='line')
```

같은 정규식이 같은 476건을 잡는다. **갭이 원천적으로 생기지 않는다.**

#### 두 테이블의 CHECK 제약이 다르다 (실측)

```
gacha_product_categories.source : name_parts | manual | collector_llm | known_product_line_term | ...
gacha_product_series.source     : name_parts | manual | collector_llm | user_log
                                  └─ known_product_line_term 없음 ⚠️

gacha_product_series.relation_type : primary | collaboration | crossover | line | unknown
                                     └─ 'line'은 허용됨 ✅
```

**`relation_type='line'`은 그대로 쓸 수 있지만 `source='known_product_line_term'`은 CHECK 위반이다.**
카테고리 쪽 값을 그대로 옮기면 마이그레이션이 죽는다.

또 시리즈 refresh의 삭제 범위는 `source = 'name_parts'` **단 하나**다.

```sql
delete from public.gacha_product_series ps
where ps.source = 'name_parts'
```

두 사실을 합치면 선택지는 둘이다.

| 안                              | 방법                                                                                | 대가                                                                               |
| ------------------------------- | ----------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| **A. source CHECK 확장** (권장) | `known_product_line_term`을 시리즈 쪽 허용값에 추가하고, refresh 삭제 목록에도 추가 | 마이그레이션 2줄 추가. **출처 구분이 남아 롤백·디버깅이 쉽다**                     |
| B. `source='name_parts'` 재사용 | 제약 변경 없음. 기존 삭제·재생성 흐름을 그대로 탐                                   | 사전 유래와 파서 유래를 구분할 수 없다. 롤백 시 어느 링크가 이번 변경분인지 모른다 |

A를 택한다. **삭제 목록 추가를 빠뜨리면 링크가 중복 누적되므로 반드시 함께 바꾼다.**

### 1단계 — 사전 대상 축 교체 (gacha-map 마이그레이션, 단일 트랜잭션)

대상 4건의 정규식 (현행 사전에서 그대로 가져온다):

```
닛코리노      にっこりーノ
판다의 구멍   パンダの穴
컵의 후치코   コップのフチ子|のフチ子      ← 대체 패턴 있음. 그대로 옮길 것
포켓토미카    ポケットトミカ
```

`20260904_expand_line_category_dictionary.sql:134-139`에서 그대로 복사한다.
**`컵의 후치코`는 `|のフチ子` 분기가 있어 이걸 빠뜨리면 `着せ替えのフチ子` 같은 상품을 놓친다.**
사전은 `gacha_categories` vocabulary(45-50행)와 `line_patterns`(134-139행) **두 곳**에 있으므로
둘 다 손봐야 한다.

1. `refresh_gacha_product_categories()`의 `line_patterns`에서 **위 4건 제거**
   (`カプセルプラレール`은 **남긴다**)
2. **`gacha_product_series.source` CHECK에 `known_product_line_term` 추가** (위 A안)
3. `refresh_gacha_product_series()`에 **브랜드 사전 블록 신설**
   - 제거한 4건의 정규식을 그대로 옮겨 `relation_type='line'`, `source='known_product_line_term'`으로 삽입
   - 함수 첫머리 삭제문의 `source` 목록에 `known_product_line_term`을 **함께 추가**
     (빠뜨리면 링크가 중복 누적된다)
   - 삽입은 반드시 삭제문 **뒤에** 온다
4. archived 시리즈 4건을 `status='active'`로, `kind` 지정
   | 이름        | kind              |
   | ----------- | ----------------- |
   | 닛코리노    | `character_brand` |
   | 판다의 구멍 | `character_brand` |
   | 컵의 후치코 | `character_brand` |
   | 포켓토미카  | `franchise`       |
   - `is_browsable`은 **건드리지 않는다** (현행 RPC가 안 쓴다)
   - `is_hidden=false`, `parent_id`는 `null` 유지
5. 빈 껍데기가 된 `line` 카테고리 4건 `status='archived'`
6. 두 MV `refresh materialized view concurrently`

> `refresh materialized view concurrently`는 유니크 인덱스를 요구한다.
> 두 MV 모두 `*_pkey`가 있어 가능하다. 단 **2단계에서 MV를 재생성하면 최초 적재는

### 2단계 — 대표 이미지 (문제 2)

배제·정렬 규칙과 후보 배열은 초안 유지. 아래만 정정한다.

- **무중단 주장 철회.** MV drop/recreate 시 인덱스·권한이 사라지므로 한 트랜잭션에서
  `create → index → grant → refresh`를 끝낸다. 짧은 잠금은 감수한다.
- **RPC 2개 모두** `RETURNS TABLE`이라 컬럼 추가 시 `drop function` 필요.
  재생성 시 `STABLE SECURITY DEFINER SET search_path TO 'public','pg_temp'`와
  `GRANT`·`COMMENT`를 현행 정의 그대로 복원한다.
- **`IMMUTABLE`은 성능 보장이 아니다.** 함수 본문을 바꾸면 MV는 자동 재계산되지 않으므로
  변경 시 강제 refresh를 절차에 포함한다.
- `.svg$` → `\.svg($|\?)`로 보강 (쿼리스트링 케이스)
