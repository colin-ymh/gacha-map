## PC 사이드 패널 UI 재사용 원칙

PC 웹의 좌측 사이드 패널(360px)은 모바일 UI를 그대로 재사용한다.
모바일과 PC 간 컴포넌트·스타일·문구를 별도로 설계하지 않는다.

### 규칙

- **컴포넌트 동일**: 버튼, 입력 필드, 태그, 선택 UI 등 모든 UI 요소는 모바일과 동일한 컴포넌트를 사용한다.
- **스타일 동일**: 버튼 색상(filled/outline), 태그 스타일, 폰트, 간격 등 시각 스타일을 모바일과 통일한다.
- **문구 동일**: 버튼 레이블, placeholder, 안내 문구 등 모든 텍스트를 모바일과 동일하게 유지한다.
- **PC 전용 추가 요소는 허용**: 내비게이션 목적의 요소(예: "← 목록으로 돌아가기")는 PC 패널에만 추가할 수 있다.
- **차이 발생 시 모바일 기준**: 모바일과 PC 간 불일치가 발견되면 모바일 버전을 정본으로 삼아 PC를 수정한다.

### 확정된 통일 기준 (모바일 기준)

#### 샵 상세 페이지

| 항목            | 확정값 (모바일 기준)          |
| --------------- | ----------------------------- |
| CTA 버튼 문구   | "제보하기"                    |
| CTA 버튼 스타일 | outline (테두리), 회색        |
| 태그 형식       | 배경색 있는 칩 (예: `피규어`) |

#### 제보 페이지

| 항목                  | 확정값 (모바일 기준)                  |
| --------------------- | ------------------------------------- |
| 제보 유형 선택 UI     | 2×2 버튼 그리드 (선택 시 주황 filled) |
| 이름 placeholder      | "이름을 입력해 주세요"                |
| 연락처 placeholder    | "이메일 또는 SNS ID"                  |
| 글자수 표시           | "0/1000"                              |
| 제출 성공 메시지 위치 | 제출 버튼 아래 (인라인)               |

## 반응형 기본 원칙

gacha-map은 모바일을 기준 UI로 설계하고, 웹(데스크톱)에서는 여유 공간을 활용해 사이드 패널을 추가하는 방식으로 확장합니다.

### 브레이크포인트

| 명칭   | 기준      | 설명                                              |
| ------ | --------- | ------------------------------------------------- |
| mobile | `< 768px` | 기준 UI. 전체 화면을 사용하며 사이드 패널 없음    |
| web    | `≥ 768px` | 사이드 패널 추가. 지도는 우측, 패널은 좌측에 위치 |

### 패널 구조 (web)

```
┌─────────────────────────────────────────────┐
│  사이드 패널 (360px 고정)  │    지도 영역    │
│  - 샵 목록 / 상세 / 제보   │  (나머지 전체)  │
└─────────────────────────────────────────────┘
```

- 사이드 패널은 항상 좌측에 고정되며 너비는 360px
- 지도는 패널 오른쪽 전체를 차지하고 항상 보임
- 패널 내 콘텐츠는 현재 상태(목록 / 상세 / 제보)에 따라 전환됨

## 메인 맵 화면

### 공통 구성

- 지도 전체화면 렌더링 (Naver Maps)
- 승인된 샵 마커 표시
- 검색바 및 태그 필터 (상단 오버레이)

### 모바일

```
┌───────────────────────┐
│  [검색바]  [필터]      │
│                       │
│         지도          │
│                       │
│  마커 클릭 →          │
│  하단 시트로 요약 카드  │
└───────────────────────┘
```

- 마커 클릭 시 하단에 요약 카드(스낵바 형태)가 올라옴
- 요약 카드 탭 → 샵 상세 페이지로 풀스크린 전환
- 목록 보기 버튼 탭 → 목록 시트(바텀시트)로 전환

### 웹

```
┌──────────────┬──────────────────┐
│  [검색바]    │                  │
│  [필터]      │      지도        │
│              │                  │
│  샵 목록     │  마커 클릭 →     │
│  (스크롤)    │  패널이 상세로    │
│              │  전환됨          │
└──────────────┴──────────────────┘
```

- 좌측 패널에 샵 목록이 기본으로 표시됨
- 마커 클릭 또는 목록 아이템 클릭 → 패널 내에서 상세 화면으로 전환

## 샵 상세 페이지

### 역할

특정 샵의 상세 정보를 보여주는 화면.
마커 클릭 또는 목록 아이템 클릭을 통해 진입.

### 데이터

`GET /api/shops/[id]` 응답 기준:

| 항목            | 표시 방식                             |
| --------------- | ------------------------------------- |
| `name`          | 상단 타이틀                           |
| `address`       | 주소 텍스트 + 클립보드 복사 버튼      |
| `description`   | 본문 텍스트                           |
| `tags`          | 태그 칩 목록                          |
| `image_urls`    | 이미지 슬라이더 (없으면 플레이스홀더) |
| `is_authorized` | 인증 뱃지 표시 여부                   |

### 액션

- 주소 탭 → 클립보드 복사
- 이미지 탭 → 이미지 전체화면 보기 (이미지가 있을 때만)
- "신고" 버튼 → 제보 페이지로 이동 (`/report?shopId=[id]`)
- 닫기(×) / 뒤로가기 → 이전 화면(목록)으로 복귀

### 모바일

```
┌───────────────────────┐
│ ← 뒤로   샵 이름      │
│───────────────────────│
│ [이미지 슬라이더]      │
│───────────────────────│
│ 샵 이름               │
│ 인증 뱃지 (있을 경우)  │
│───────────────────────│
│ 주소      [복사]       │
│───────────────────────│
│ #태그1  #태그2         │
│───────────────────────│
│ 설명 본문              │
│                       │
│───────────────────────│
│       [제보하기]       │
└───────────────────────┘
```

- 전체 화면을 사용하는 독립 페이지로 렌더링
- 상단에 뒤로가기 버튼으로 맵 화면 복귀

### 웹

```
┌──────────────┬──────────────────┐
│  [이미지]    │                  │
│  샵 이름     │      지도        │
│  인증 뱃지   │  (해당 샵 마커   │
│  주소 [복사]  │   중심 포커스)   │
│  #태그들     │                  │
│  설명 본문   │                  │
│  [제보하기]  │                  │
│  [목록으로←] │                  │
└──────────────┴──────────────────┘
```

- 좌측 사이드 패널 내에서 렌더링 (지도는 유지됨)
- 지도는 해당 샵 마커가 중심에 오도록 자동 이동
- 목록으로 버튼(패널 하단 또는 상단)으로 목록 패널로 복귀
- URL은 `/shop/[id]`로 변경되어 직접 링크 공유 가능

### 라우팅

| 환경   | 진입 경로                       | URL 변경                                 |
| ------ | ------------------------------- | ---------------------------------------- |
| 모바일 | 마커 탭 → 요약 카드 탭          | `/shop/[id]`                             |
| 웹     | 마커 클릭 또는 목록 아이템 클릭 | `/shop/[id]` (URL만 변경, 레이아웃 유지) |

## 제보 페이지

### 역할

신규 샵 제보 또는 기존 샵 정보 수정 요청을 접수하는 화면.
누구나 접근 가능 (비로그인 허용).

### 진입 경로

- 샵 상세 페이지 내 "제보하기" 버튼 → 해당 샵 ID 연결
- 맵 화면 플로팅 버튼 "새 샵 제보" → 샵 ID 없이 신규 제보

### 폼 항목

| 항목           | 타입                                          | 필수   | 비고                                      |
| -------------- | --------------------------------------------- | ------ | ----------------------------------------- |
| 제보 유형      | 라디오 (new_shop / fix_info / closed / other) | 예     | 유형에 따라 content 안내 문구 조건부 표시 |
| 제보 내용      | 텍스트에어리어                                | 예     | 최소 10자, 최대 1,000자                   |
| 제보자 이름    | 텍스트                                        | 아니오 | 최대 50자, 익명 허용                      |
| 제보자 연락처  | 텍스트                                        | 아니오 | 최대 100자, 형식 검사 없음                |
| shop_id (내부) | 자동 설정                                     | —      | 샵 상세 진입 시 자동 연결, 사용자 비노출  |

#### 제보 유형별 안내 문구

- `new_shop`: "샵 이름, 주소, 특징을 포함해 주세요"
- `fix_info` / `closed` (샵 상세 미진입 시): "샵 이름을 포함해 주세요"

### 제출 후 처리

- 성공: 폼 초기화 + 인라인 완료 메시지 표시 ("제보가 접수되었습니다. 검토 후 반영됩니다.") — 별도 페이지 이동 없음
- 실패 (네트워크/서버 오류): 폼 유지 + "제보 전송에 실패했습니다. 다시 시도해 주세요." 표시
- 필수 항목 미입력: 제출 차단 + 해당 필드 하단 인라인 오류 메시지
- 제출 중 중복 클릭 방지: 버튼 비활성화 (로딩 상태 유지)

### 모바일

```
┌───────────────────────┐
│ ← 뒤로   제보하기     │
│───────────────────────│
│ 제보 유형             │
│ ○ 새 샵 제보          │
│ ○ 정보 수정 요청      │
│ ○ 폐업 제보           │
│ ○ 기타                │
│───────────────────────│
│ 제보 내용             │
│ [안내 문구...]        │
│ [                   ] │
│ [                   ] │
│                       │
│ 제보자 이름 (선택)     │
│ [___________________] │
│                       │
│ 연락처 (선택)          │
│ [___________________] │
│───────────────────────│
│       [제출하기]       │
└───────────────────────┘
```

- 전체 화면의 독립 페이지로 렌더링
- 상단 뒤로가기로 샵 상세 또는 맵으로 복귀

### 웹

```
┌──────────────┬──────────────────┐
│ ← 상세로     │                  │
│ 제보하기     │      지도        │
│              │  (관련 샵 마커   │
│ [제보 폼]    │   또는 기본 뷰)  │
│              │                  │
│ [제출하기]   │                  │
└──────────────┴──────────────────┘
```

- 좌측 사이드 패널 내에서 렌더링 (지도는 유지됨)
- 샵 상세에서 진입했을 경우 지도는 해당 샵 마커 포커스 유지
- 패널 상단에 "← 상세로 돌아가기" 버튼으로 상세 패널 복귀
- URL은 `/report?shopId=[id]` 또는 `/report` (신규 제보)로 변경

### 라우팅

| 진입             | 모바일 URL            | 웹 URL                | 비고          |
| ---------------- | --------------------- | --------------------- | ------------- |
| 샵 상세에서 제보 | `/report?shopId=[id]` | `/report?shopId=[id]` | URL 공유 가능 |
| 신규 샵 제보     | `/report`             | `/report`             | 샵 ID 없음    |

## 패널 전환 플로우 (웹 요약)

```
기본 상태: 좌측 패널 = 샵 목록
     ↓ 마커 클릭 또는 목록 아이템 클릭
상세 상태: 좌측 패널 = 샵 상세  (URL: /shop/[id])
     ↓ 신고 버튼 클릭
제보 상태: 좌측 패널 = 제보 폼  (URL: /report?shopId=[id])
     ↓ 제출 완료 또는 뒤로가기
상세 상태 또는 목록 상태로 복귀
```

패널 전환은 지도를 다시 렌더링하지 않고 패널 내 컨텐츠만 교체합니다.

## 어드민: 제보 검토 화면

### 경로

`/admin/reports`

### 역할

사용자 제보(`reports`)를 검토 상태로 관리하는 어드민 전용 화면.
로그인한 admin role 사용자만 접근 가능.

### 목록

- 기본 목록은 `status = 'pending'` 인 제보를 표시
- 각 제보 항목: 관련 샵, 제보 유형, 제보 내용, 제보자 정보, 제출일
- 액션 버튼: **검토 완료** / **처리 완료**

### 상태 처리 플로우

| 액션      | 결과                         | 비고                                      |
| --------- | ---------------------------- | ----------------------------------------- |
| 검토 완료 | `reports.status = 'reviewed'` | 제보 내용을 확인했지만 추가 처리 여지 있음 |
| 처리 완료 | `reports.status = 'resolved'` | 제보 처리를 마친 상태                     |

신규 샵 후보를 실제 `shops` 데이터로 생성하거나 기존 샵에 연결하는 검수 기능은 별도 `temporal_shops` 기반 후속 기능으로 분리합니다.

### 화면 구조

```
┌──────────────────────────────────────────────────────┐
│ 제보 검토                               [pending: 12] │
│──────────────────────────────────────────────────────│
│ 관련 샵    유형          제보 내용 요약   [검토] [완료] │
│──────────────────────────────────────────────────────│
│ 관련 샵    유형          제보 내용 요약   [검토] [완료] │
└──────────────────────────────────────────────────────┘
```

### 라우팅

| 경로             | 설명           |
| ---------------- | -------------- |
| `/admin/reports` | 제보 검토 목록 |

## 어드민: 샵 목록 화면

### 경로

`/admin/shops`

### 역할

등록된 샵 전체를 관리하는 어드민 화면.
샵을 무시(hidden) 상태로 전환하거나 복원할 수 있다.
무시된 샵은 메인 서비스(지도/목록)에서 자동으로 제외된다 (RLS: `status = 'active'`만 공개).

### 탭 구조

| 탭        | 대상                | 가능한 액션            |
| --------- | ------------------- | ---------------------- |
| 전체 샵   | `status = 'active'` | 무시하기 (→ `hidden`)  |
| 무시된 샵 | `status = 'hidden'` | 무시 해제 (→ `active`) |

### 무시 기능 규칙

- 무시 on/off는 토글 형태로 인라인 처리 (페이지 이동 없음)
- 무시된 샵은 `/api/shops` 응답에 포함되지 않음 (RLS에서 처리, 별도 필터 불필요)
- 무시 해제 시 즉시 메인 서비스에 노출됨

### 화면 구조

```
┌──────────────────────────────────────────────────────┐
│ 샵 관리                                               │
│ [전체 샵 (124)]  [무시된 샵 (5)]                      │
│──────────────────────────────────────────────────────│
│ 샵 이름     주소              인증 여부   [무시 ●/○]  │
│ 가챠월드    서울시 강남구...   ✓ 인증      [무시 ●]   │
│ 뽑기천국    서울시 마포구...   -           [무시 ○]   │
└──────────────────────────────────────────────────────┘
```

- 무시 토글 `●` = 무시 중(hidden), `○` = 정상(active)
- 인증 여부: `is_authorized = true` 이면 인증 뱃지 표시
