# 배지 시스템 기획 설계

## Context

현재 배지 시스템은 퀵리포트 `contribution_count` 기반 4개 배지만 존재. 사용자 참여 동기 부여와 신뢰 신호로서의 역할이 부족. 배지 트랙 다양화, 대표 배지 노출, 어뷰징 방지를 포함한 완전한 게이미피케이션 시스템으로 확장.

## 목표

- 사용자 행동(퀵리포트, 리뷰, 신고, 위시리스트)에 따른 독립 배지 트랙
- 스토리텔링 네이밍 (숫자/단계 비공개, 발견 재미)
- 대표 배지 → 프로필 헤더 + 리뷰 카드 노출
- 어뷰징 방지 + 이상 감지 플래그
- 어드민에서 배지 메타데이터 수정 가능

## 배지 트랙 구조

총 **6개 행동 트랙** + **1개 특별 배지**. 각 트랙 3단계, 단계별 고유 이름, **임계값 비공개**.

| 트랙            | 기반 행동       | 단계 1 → 2 → 3 (예시)            |
| --------------- | --------------- | -------------------------------- |
| 퀵리포트        | 퀵리포트 제출   | 눈팅러 → 정보통 → 가차신         |
| 샵 리뷰         | 리뷰 작성       | 수다쟁이 → 리뷰어 → 구루         |
| 신규샵 제보     | new_shop 신고   | 발굴러 → 탐험가 → 지도 제작자    |
| 폐업 신고       | closed 신고     | 정리왕 → 추적자 → 현실주의자     |
| 정보수정        | fix_info 신고   | 꼼꼼이 → 팩트체커 → 진실 수호자  |
| 위시리스트      | 위시리스트 추가 | 찜 초보 → 수집가 → 욕망 큐레이터 |
| **운영자 배지** | 관리자 승인     | (단일) 공식 운영자               |

**네이밍/아이콘/임계값은 어드민에서 수정 가능** — DB에 저장, 하드코딩 금지.

## 어뷰징 방지

### 배지 카운트 제한

- 행동 자체는 무제한 허용 (단골 샵에 여러 리뷰 가능)
- 배지 카운트: **동일 사용자 + 동일 샵 + 동일 행동 유형 → 주 1회**

### 이상 행동 감지 → 어드민 플래그

자동 감지 후 어드민 대시보드에 플래그 (카운트는 정상 적용, 어드민이 검토):

- 1시간 내 동일 유형 행동 10건 이상
- 가입 후 7일 이내 배지 2단계 이상 달성
- 상품 가격 정상 범위 이탈 (100엔 미만 or 10,000엔 초과)

### 가격 이상값 처리

- 소프트 경고: 범위 이탈 시 사용자에게 확인 경고
- 확인 후 제출 허용 → 어드민 플래그 생성
- 하드 블록 없음 (실제 500엔, 1000엔 가차 존재)

## UI/UX

### 배지 페이지 (`/mypage/badges`, 모바일: `/badges`)

- 획득 배지: 아이콘 + 이름 + 설명 표시
- 미획득 배지: 실루엣 + 자물쇠 아이콘만, 힌트/진행도 없음
- 운영자 배지: 획득 시 상단 별도 섹션 표시

### 대표 배지 설정

- 획득 배지 중 1개 선택 → 대표 배지 지정
- 미설정 시 기본값 없음 (노출 안 함)

### 프로필 헤더

- 대표 배지 아이콘 + 이름 표시
- 미설정 시 해당 영역 숨김

### 리뷰 카드

- 리뷰 작성자 이름 옆에 대표 배지 아이콘 소형 표시
- 미설정 시 아이콘 없음

## DB 설계 방향

### `badge_definitions` (어드민 관리)

```
id, track, tier (1/2/3), name, description, icon_url, threshold, created_at, updated_at
```

### `user_badges`

```
user_id, badge_definition_id, earned_at
```

### `user_profiles` 확장

```
main_badge_id (FK → user_badges)
```

### `badge_count_log` (주간 카운트 관리)

```
user_id, shop_id, action_type, week_start, counted_at
UNIQUE(user_id, shop_id, action_type, week_start)
```

- `week_start`: 해당 주 월요일 00:00 UTC (캘린더 주 기준, 롤링 7일 아님)

### `abuse_flags`

```
user_id, flag_type, detail, created_at, reviewed_at, reviewed_by
```

## 기존 코드와의 관계

- `contribution_count` → 퀵리포트 트랙 카운트로 마이그레이션
- `shop_quick_reports` UNIQUE 제약 → 주간 카운트 로직으로 대체
- 기존 배지 상수 (`packages/shared/src/types/index.ts`) → DB 기반으로 전환
- 기존 배지 페이지 (`apps/mobile/app/badges.tsx`, `apps/web/.../badges/page.tsx`) → 새 설계 기반으로 재작성

## 어드민 기능 범위

- 배지 이름 / 아이콘 / 설명 / 임계값 수정
- 어뷰징 플래그 확인 및 처리
- 운영자 배지 승인

## 스코프 외

- 포인트/쿠폰 시스템
- 배지 공유 (SNS)
- 배지 거래/양도
- 체크인 기능

## 검증 방법

1. 퀵리포트 제출 → 해당 트랙 카운트 증가 확인
2. 동일 샵 동일 주에 재제출 → 카운트 증가 안 함 확인
3. 임계값 달성 → 배지 자동 부여 확인
4. 대표 배지 설정 → 프로필 헤더 + 리뷰 카드에 노출 확인
5. 이상 행동 시뮬레이션 → 어드민 플래그 생성 확인
6. 가격 이상값 입력 → 경고 팝업 + 제출 후 플래그 확인
7. 어드민에서 배지 이름 수정 → 즉시 반영 확인

## 리스크 / 확인 필요 항목

- 기존 `contribution_count` 마이그레이션 시 기존 사용자 배지 소급 부여 여부 결정 필요
- 위시리스트 카운트 트래킹 인프라 현재 없음 → 추가 필요
- 리뷰 시스템 테이블 구조 확인 후 카운트 로직 설계 필요
- 어드민 대시보드 현재 구조 파악 필요 (플래그 UI 추가 위치)
- 배지 이미지/아이콘 에셋 관리 방식 결정 필요 (Supabase Storage vs CDN)
